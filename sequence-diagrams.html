SmartHealth — Sequence Diagrams

Three core Temporal-orchestrated flows

1 · User Creation Workflow

Client registers → auth-service saves user (status=pending) + fires UserCreationWorkflow → on success, user activated → on failure, all created records are compensated and user is deleted so they can retry

request response activate compensate

2 · Provider Availability Setup Workflow

Admin calls setup-availability → triggers ProviderAvailabilityWorkflow → worker creates one availability slot per matching day for the next 30 days

request response on failure

3 · Appointment Booking Workflow

Client books appointment → 202 immediately → Temporal validates entities, checks availability slot, checks conflicts → creates appointment as "confirmed" only if all pass

request response creates record on failure

4 · Analytics — TimescaleDB Event Ingestion & Filtered Query

Appointment events flow from Kafka into TimescaleDB. Clients query /analytics/filter using time_bucket() to get daily aggregates filtered by clinic or provider.

request / query response persists to TimescaleDB client query
